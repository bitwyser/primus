01

Know the exam you're actually sitting

The v3 exam is different from the old eWPTX. If you read a writeup describing a 7-day exam with a written report, that's the retired v2 — good for technique ideas, wrong on logistics.

What it tests

You get access to a modern web application and must find and exploit real vulnerabilities, then answer questions whose answers only exist if you actually compromised the target. No multiple-choice-only path.

How it's graded

Auto-graded. Results land within a few hours, with a per-domain score report so you can see exactly where you were weak.

Voucher & retake rules

Vouchers expire 180 days after purchase. If you don't pass, the free retake must be done within 14 days — and both attempts must finish before the voucher expires.

Prerequisites

None formal. It's built for intermediate-to-advanced testers. Your CEH Master + a year of web/API AppSec is a solid launchpad — this plan assumes that foundation and skips beginner ground.

Verify the live numbers. The ~18-hour / ~45-question / 75% figures come from candidate reports and prep trackers, not the official page. INE tweaks exam mechanics between cohorts — confirm the current format on your INE certification dashboard once your voucher is active.
02

The 12-week plan

Weighted toward where the marks are: API gets three full weeks, injection and auth get two each, and the fundamentals you already know get compressed. Tick items as you go — your readiness meter fills up top.

WK 1–2

Foundations, fast — recon & methodology (25%)

Goal: lock down a professional workflow and the eWPTX-flavoured recon. You know OWASP basics — spend the time on scale and on the two objectives people forget: mass asset discovery and git-secret hunting.

  • Build your lab: Burp Suite (Community is fine), OWASP ZAP, and self-hosted targets (Juice Shop, DVWA, crAPI)
  • Read the OWASP WSTG methodology end-to-end; turn it into your own testing checklist
  • Recon at scale: subfinder/amass → httpx → ffuf content discovery; practise on a lab domain
  • Secret hunting: gitleaks / trufflehog against a seeded repo (an explicit exam objective)

Free: OWASP WSTG · PortSwigger Academy (Recon path) · HackTricks

WK 3–4

Injection — SQL, NoSQL, XML (15%)

Goal: exploit injection by hand before automating. Blind and time-based SQLi are where candidates stall; NoSQLi and XXE are the modern twists eWPTX loves.

  • Clear all PortSwigger SQL injection labs — error-based, blind boolean, time-based, OOB
  • Master sqlmap: --dump, tamper scripts, --os-shell, and when NOT to use it
  • NoSQL injection (MongoDB operator injection, auth bypass) via PortSwigger + PayloadsAllTheThings
  • XXE: file read, SSRF-via-XXE, blind OOB exfiltration

Free: PortSwigger Academy · PayloadsAllTheThings · HackTricks

WK 5–6

Authentication & sessions (15%)

Goal: break modern auth. JWT and OAuth/OIDC flaws carry disproportionate weight — get fluent in token tampering and flow abuse.

  • JWT attacks: alg=none, key confusion (RS256→HS256), weak-secret cracking with jwt_tool / hashcat
  • OAuth 2.0 / OpenID Connect: redirect_uri abuse, state/CSRF, token leakage — PortSwigger OAuth labs
  • Session flaws: fixation, hijacking, predictable tokens; SSO / SAML weaknesses
  • Credential stuffing & brute-force logic — where rate limiting is (and isn't) enforced

Free: PortSwigger Academy (Auth, JWT, OAuth) · jwt.io · HackTricks

WK 7–9

API penetration testing — the 25% block

Goal: this is a quarter of the exam and the biggest single lever. Cover REST and GraphQL, the OWASP API Top 10, and rate-limit bypass. Practise on real vulnerable APIs, not just reading.

  • APIsec University: "API Security Fundamentals" + "API Penetration Testing" (free courses)
  • BOLA / BFLA / mass assignment / excessive data exposure on crAPI & VAmPI
  • GraphQL: introspection, batching attacks, injection — on Damn Vulnerable GraphQL App (DVGA) + InQL
  • PortSwigger API testing labs + method tampering (PUT/DELETE/PATCH), parameter manipulation
  • Rate-limiting: detection, resource exhaustion, and documented bypass techniques

Free: APIsec University · OWASP API Security Top 10 · PortSwigger Academy · crAPI / VAmPI / DVGA

WK 10

Server-side attacks (10%)

Goal: the high-impact server-side chain — SSRF into cloud metadata, deserialization to RCE, LDAP injection, and SSTI as a bonus.

  • SSRF: internal port scans, cloud metadata (169.254.169.254), filter bypasses
  • Deserialization to RCE across Java, PHP, .NET, Python (ysoserial concepts)
  • LDAP injection for auth bypass / data extraction
  • SSTI identification & exploitation per engine (Jinja2, Twig, FreeMarker)

Free: PortSwigger Academy (SSRF, Deserialization) · HackTricks · PayloadsAllTheThings

WK 11

Filter evasion & WAF bypass (10%)

Goal: get payloads past defenses. Encoding, obfuscation, fragmentation and content-type tricks — chained onto the SSRF/XXE/injection you already learned.

  • Encoding & obfuscation ladders (URL, double, unicode, case, comment injection)
  • Payload fragmentation & content-type manipulation to slip filters
  • Work through Awesome-WAF + PayloadsAllTheThings WAF-bypass notes against a filtered lab
  • Re-run earlier SQLi/XSS/SSRF exploits, but now against input validation

Free: Awesome-WAF (GitHub) · PayloadsAllTheThings · PortSwigger Academy

WK 12

Full simulations + chaining + weak-area cleanup

Goal: stop learning topics, start chaining them under time pressure — that's the real skill the exam tests. Then buy your voucher already exam-ready.

  • Timed end-to-end runs: fully compromise Juice Shop and crAPI, recon → exploit → pivot
  • Build a repeatable note-taking template (finding → evidence → the question it answers)
  • Re-test your two lowest domains from self-assessment; close the gaps
  • Do the free OpenExamPrep eWPTX question bank to shake out theory blind spots
  • Buy the voucher / bundle in the Black Friday sale and schedule the exam

Free: OWASP Juice Shop · crAPI · OpenExamPrep question bank · dev-angelist eWPTXv3 notes

25%

The largest domain. Hands-on tests of API endpoints; automation for API vuln discovery; parameter manipulation; and rate-limiting attacks (DoS, resource exhaustion) plus documented bypasses. Covers REST, GraphQL and OAuth flows.

D6

Server-Side Attacks

10%

SSRF against internal services; deserialization to code execution / privilege escalation; LDAP injection for auth bypass and data extraction.

PortSwigger (SSRF, Deserialization) · ysoserial · HackTricks

Filter Evasion & WAF Bypass

10%

Analyse WAF rules for weak configs; bypass via encoding, obfuscation, payload fragmentation; defeat input validation, focused on SSRF & XXE.

Awesome-WAF · PayloadsAllTheThings (WAF) · PortSwigger

05

Exam-day playbook

The exam rewards methodical chaining and good notes over raw speed. With ~18 hours, thoroughness beats rushing.

Methodology run the same loop everywhere

  • Map first, exploit second. Full recon and endpoint mapping before you fire a single payload — findings gate later objectives.
  • Some objectives unlock only after earlier ones. If you're stuck, you're probably missing a prerequisite finding, not a payload.
  • Enumerate every HTTP method and parameter on every endpoint — the exam hides functionality behind the ones devs forgot to lock.

Notes & time your answers live in your notes

  • Log finding → evidence → the question it answers as you go. The questions are tied to what you exploited; disorganised notes cost real marks.
  • Use the whole clock. Passers routinely finish well inside the window — the time is generous, so be thorough, take breaks, revisit enumeration when blocked.
  • Exam desktop ships with the wordlists you need — don't burn time chasing external lists.

If you fail attempt 1 it happens to strong testers

  • The free retake must be within 14 days — so debrief immediately using your per-domain score report.
  • Failing often just means one blocked chain (e.g. a privesc step). Drill that exact gap, then go again.

Stay legal & safe habits that transfer to work

  • Only test the provided exam scope and your own lab targets — nothing else.
  • Everything in this manual assumes practice on apps you own or are explicitly authorised to test.
